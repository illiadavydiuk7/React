# ЛР-6 (альтернативна версія). Форма бронювання на Formik та Yup

Альтернативна реалізація лабораторної роботи № 6 курсу «Розробка вебзастосунків на React»: та сама форма бронювання столика та підписки на новини, але замість зв'язки **React Hook Form + Zod** використано **Formik + Yup**.

## Команди

`npm install` виконуйте в корені репозиторію `react-labs`, решту — у теці `lab-6-alt/`:

- `npm run dev`: dev-сервер на http://localhost:5173
- `npm run lint`: ESLint
- `npm run format:check`: перевірка форматування Prettier
- `npm run build`: production-збірка в `dist/`

## Порівняння з React Hook Form і Zod

### Бібліотеки, версії та актуальність

- **Основна версія (`lab-6`):**
  - `react-hook-form` (`^7.92.0`) — останній реліз у листопаді 2026 року (4 дні тому).
  - `zod` (`^4.6.7`) — останній реліз у жовтні 2026 року (місяць тому).
- **Альтернативна версія (`lab-6-alt`):**
  - `formik` (`^2.4.9`) — останній реліз вийшов у листопаді 2025 року (рік тому).
  - `yup` (`^1.7.1`) — останній реліз вийшов у 2025 році (близько року тому).

### Відповідність концепцій та API

| React Hook Form + Zod (`lab-6`)          | Formik + Yup (`lab-6-alt`)                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `register('name')`                       | Пропси `name`, `value={formik.values.name}`, `onChange={formik.handleChange}`, `onBlur={formik.handleBlur}`                             |
| `Controller` для `GuestsStepper`         | Пряма передача `value={formik.values.guests}` та `onChange={(val) => formik.setFieldValue('guests', val)}`                              |
| `useWatch({ control, name: 'comment' })` | Пряме звернення до стану `formik.values.comment`                                                                                        |
| `handleSubmit(onValid)`                  | `formik.handleSubmit` + ручний виклик `formik.validateForm()` і `formik.setTouched(...)` для переведення фокусу на перше помилкове поле |
| `zodResolver(bookingSchema)`             | Параметр `validationSchema: bookingSchema` у `useFormik` та `bookingSchema.cast(values)` перед відправленням                            |
| `reset()`                                | `formik.resetForm()`                                                                                                                    |

### Розмір JS-файлу збірки (`npm run build`)

- `lab-6` (React Hook Form + Zod): **353.70 kB** (`gzip: 109.38 kB`).
- `lab-6-alt` (Formik + Yup): **305.57 kB** (`gzip: 95.48 kB`).

_(Бандл з Formik + Yup виявився меншим на ~48 kB, оскільки Zod v4 містить більший набір вбудованих парсерів і утиліт типізації порівняно з Yup)._

### Рендери під час введення в поле «Ім'я» (React DevTools → Highlight updates)

- `lab-6` (**React Hook Form**): жоден компонент не рендериться під час друку, бо стандартні поля працюють як неконтрольовані через `ref`.
- `lab-6-alt` (**Formik**): на кожну введену літеру перемальовуються `BookingForm` та дочірній `GuestsStepper`, оскільки Formik зберігає значення всіх полів у стані React і оновлює компонент при кожній події `onChange`.

### Висновок

Для наступного проєкту я обрав би зв'язку **React Hook Form + Zod**. Попри трохи більший розмір збірки, вона не викликає зайвих ререндерів усієї форми під час введення тексту, автоматично керує фокусом на першому невалідному полі та забезпечує зручне виведення TypeScript-типів зі схеми без дублювання. Formik простіший у базовому розумінні контрольованого стану, проте потребує більше ручного коду для доступності й фокусу, а також фактично не отримує оновлень протягом останнього року (останній реліз `2.4.9` вийшов ще у листопаді 2025 року).
